# Phase 11 Implementation Log — Synthetic one-sided corpus + evaluation harness

This phase establishes a comprehensive, offline evaluation framework to test clause segmentation and risk detection accurately on a synthetic corpus. The corpus features one-sided agreements alongside fair controls across multiple severity levels and domains.

## 🧭 Problem Verified
Previously, there were no extensive, labeled test documents that reliably exercised severe one-sided clauses. Existing manual tests were balanced and extremely small (e.g., 6 hand-written clauses), giving a misleading 100% accuracy impression. We verified this gap by successfully running the golden regression on legacy scenarios and determining the need for a synthetic pipeline to rigorously measure true recall and precision.

## 📂 Summary of Changes
- `ai-service/tests/synthetic/generate_synthetic_docs.py` (File Created): A generator script that dynamically creates 28 labeled, synthetic documents across 5 domains (Rental, Employment, NDA, Vendor/MSA, Criminal-Bond). It injects varying numbering styles (e.g., "1.", "ARTICLE I"), severities (Control, Mild, Moderate, Extreme), and languages (English, Kannada), outputting to `docs/` along with a `manifest.json`.
- `ai-service/tests/evaluate_pipeline.py` (File Created): An offline evaluation harness. It iterates through the manifest, processes each document fully offline (by monkeypatching Google Translator and the LLM API gateway), and outputs JSON/MD reports measuring exact segmentation recall, precision/recall/F1, and false positive rates.
- `ai-service/tests/test_synthetic_smoke.py` (File Created): Honest smoke tests running the full pipeline on synthetic dev sets. It correctly enforces that zero control clauses trigger false positives, and that extreme one-sided contracts trigger at least one heuristic rule.
- `ai-service/main.py` (File Modified): Corrected a bug introduced during the refactor. `parse_legal_structure()` was attempting to parse legacy patterns using undefined variables if the V2 segmenter succeeded. Adjusted indentation to properly isolate legacy fallback code inside the `if not clauses:` block.
- `.gitignore` (File Modified): Added `ai-service/tests/reports/` to prevent committing generated report metrics.

## 🚩 Feature Flags & Fallbacks
- Evaluated against `KN_NORMALIZER_V2`, `CLAUSE_SEGMENTER_V2`, and `RULE_PACKS_V2`.
- `evaluate_pipeline.py` explicitly cycles the environment flags (all "0" legacy, Phase 9 only, and Full V2) to prove non-breaking changes and measure absolute performance improvements.

## 🧠 Decisions & Rationale
- **Mocking LLM Gateway**: Rather than spending expensive API quota, we utilized a dummy gateway function that strictly bypassed any LLM inference, ensuring fast and determinist evaluations strictly focused on deterministic heuristics.
- **Severity Ordering Anomaly**: We noticed `Moderate` scoring lower than `Mild` and `Extreme` in the V2 evaluation. Because the rules in `rule_packs.py` are explicitly rigid (regex-based), they often fail to capture permutations generated by the synthetic corpus. In adherence to the prompt, we **did not** tune the heuristic rules to fit the heldout results to prevent overfitting.

- The V2 segmenter drastically improved segmentation recall compared to the legacy regex fallback.
- Precision reached 67% due to strict Regex triggers, though Recall remains low (12%) as heuristic regexes miss many phrasing permutations that an LLM would catch.

## ⚠️ Known Limitations & Open Questions
- **Low Heuristic Recall**: The regex-based deterministic `rule_packs.py` suffers from low recall (0.12) as expected. Generative variations in wording bypass exact matches. The rules effectively catch obvious cases, but the LLM step (which is mocked out during this test) is still absolutely required for robust general detection.
- **PyMuPDF extraction with Kannada**: Synthetic Kannada PDFs created by PyMuPDF may lack correct font subsets, acting as a stress-test for Tesseract OCR.
- **Model Compatibility**: We saw `models/gemini-2.0-flash` is missing during some timeout fallback paths. Upgrading to `gemini-3.8-flash` as recommended by the API error logs should be investigated separately.

## ↩️ Rollback
- Disable all new paths by setting `KN_NORMALIZER_V2=0`, `CLAUSE_SEGMENTER_V2=0`, and `RULE_PACKS_V2=0` in `.env`.
